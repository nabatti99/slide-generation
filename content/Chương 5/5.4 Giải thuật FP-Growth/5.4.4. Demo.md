## Slide 90 — Demo Python: FP-Growth

### Mục tiêu demo

Sử dụng cùng ma trận giao dịch 0/1 và cùng ngưỡng `min_support` như phần Apriori để:

1. Tìm frequent itemset bằng `fpgrowth()`
2. So sánh số frequent itemset và thời gian chạy với `apriori()`
3. Sinh luật kết hợp bằng `association_rules()`
4. Lọc luật theo `confidence` và `lift`

> **Trọng tâm khi trình chiếu:** không đi sâu vào từng dòng lệnh; theo dõi luồng dữ liệu từ ma trận giao dịch đến frequent itemset, luật kết hợp và kết quả so sánh.

FP-Growth và Apriori đều hướng đến việc tìm tập frequent itemset hoàn chỉnh theo cùng ngưỡng support; khác biệt là FP-Growth dùng FP-tree và khai phá tăng trưởng mẫu, còn Apriori sinh candidate itemset theo từng mức.

### Mã Python

```python
import pandas as pd
from time import perf_counter
from mlxtend.frequent_patterns import apriori, fpgrowth, association_rules

# Ma trận 0/1 đã sử dụng ở phần Apriori
transactions = pd.DataFrame({
    "I1": [1, 0, 0, 1, 1, 0, 1, 1, 1],
    "I2": [1, 1, 1, 1, 0, 1, 0, 1, 1],
    "I3": [0, 0, 1, 0, 1, 1, 1, 1, 1],
    "I4": [0, 1, 0, 1, 0, 0, 0, 0, 0],
    "I5": [1, 0, 0, 0, 0, 0, 0, 1, 0]
}, dtype=bool)

min_support = 2 / len(transactions)

start = perf_counter()
freq_apriori = apriori(
    transactions,
    min_support=min_support,
    use_colnames=True
)
time_apriori = perf_counter() - start

start = perf_counter()
freq_fpgrowth = fpgrowth(
    transactions,
    min_support=min_support,
    use_colnames=True
)
time_fpgrowth = perf_counter() - start
```

Dữ liệu phải có dạng one-hot/0–1, trong đó mỗi hàng là một giao dịch, mỗi cột là một item và giá trị `True` hoặc `1` biểu thị item xuất hiện trong giao dịch. FP-Growth trong thư viện được dùng với cùng ngưỡng `min_support` để bảo đảm kết quả có thể so sánh trực tiếp với Apriori.

## Slide 92 — Kiểm tra kết quả và thời gian

### Mã so sánh

```python
freq_apriori["itemsets"] = freq_apriori["itemsets"].apply(frozenset)
freq_fpgrowth["itemsets"] = freq_fpgrowth["itemsets"].apply(frozenset)

same_itemsets = set(freq_apriori["itemsets"]) == set(freq_fpgrowth["itemsets"])

comparison = pd.DataFrame({

    "Số frequent itemsets": [

        len(freq_fpgrowth)

    "Thời gian chạy (giây)": [
        time_apriori,

    ]

print(comparison)
print("Hai tập frequent itemset giống nhau:", same_itemsets)
```

### Kết quả kỳ vọng

| Nội dung kiểm tra | Kỳ vọng |
|---|---|
| Số frequent itemset | Bằng nhau |
| Các itemset được trả về | Giống nhau |
| Support của từng itemset | Giống nhau |
| Thời gian chạy | Có thể khác nhau |

> **Cùng dữ liệu và cùng `min_support` thì Apriori và FP-Growth phải trả về cùng tập frequent itemset. Thời gian chạy có thể khác vì Apriori sinh–kiểm tra candidate itemset, còn FP-Growth nén giao dịch vào FP-tree và khai phá theo các cây điều kiện.**

Apriori xác định frequent itemset qua các candidate set theo từng mức, còn FP-Growth tìm cùng loại kết quả mà không cần sinh candidate itemset, nhờ nén dữ liệu thành FP-tree và khai phá đệ quy các conditional database. 

### Lưu ý sư phạm

Với bộ dữ liệu 9 giao dịch rất nhỏ, chênh lệch thời gian có thể không ổn định hoặc không đáng kể do chi phí khởi tạo hàm và môi trường chạy. Lợi thế hiệu năng của FP-Growth thường thể hiện rõ hơn khi số frequent item, số giao dịch hoặc độ dài pattern tăng lên.

## Slide 93 — Sinh và lọc luật kết hợp

### Mã Python

```python
rules = association_rules(
    freq_fpgrowth,
    metric="confidence",
    min_threshold=0.70
)

rules_filtered = rules[
    (rules["confidence"] >= 0.70) &
    (rules["lift"] > 1)
].copy()

rules_filtered = rules_filtered[
    [
        "antecedents",
        "consequents",
        "support",
        "confidence",
        "lift"
    ]
].sort_values(
    by=["lift", "confidence", "support"],
    ascending=False
)

print(rules_filtered)
```

### Cách diễn giải

| Chỉ số | Ý nghĩa |
|---|---|
| `support` | Tỷ lệ giao dịch chứa đồng thời vế trái và vế phải |
| `confidence` | Xác suất có vế phải khi giao dịch đã có vế trái |
| `lift` | Mức độ đồng xuất hiện so với trường hợp hai vế độc lập |
| `lift > 1` | Liên hệ dương giữa vế trái và vế phải |
| `lift = 1` | Hai vế gần như độc lập |
| `lift < 1` | Liên hệ âm |

Ví dụ, luật \(\{I1, I5\} \rightarrow \{I2\}\) có confidence 100% trong dữ liệu minh họa vì cả hai giao dịch chứa \(I1\) và \(I5\) đều đồng thời chứa \(I2\); tuy nhiên vẫn cần xem thêm support và lift trước khi đưa ra quyết định kinh doanh. 

> **Không dừng ở confidence cao:** một luật có confidence cao chưa chắc hữu ích nếu consequent vốn đã xuất hiện rất thường xuyên; lift giúp đánh giá mức liên hệ vượt lên trên tần suất nền.

## Slide 94 — Bài tập ứng dụng

### Yêu cầu

Với **cùng ma trận giao dịch** và **cùng `min_support`**:

1. Chạy `apriori()` và `fpgrowth()`
2. So sánh số frequent itemset
3. Kiểm tra hai tập itemset có giống nhau hay không
4. So sánh support của từng itemset
5. Đo thời gian chạy của mỗi thuật toán
6. Sinh luật từ kết quả FP-Growth; lọc theo `confidence >= 0.70` và `lift > 1`

### Câu hỏi phân tích

> **Vì sao Apriori và FP-Growth phải trả về cùng frequent itemset, nhưng thời gian chạy có thể khác nhau?**

### Gợi ý trả lời

- Hai thuật toán áp dụng cùng định nghĩa frequent itemset: itemset có support không nhỏ hơn `min_support`
- Khi dữ liệu và ngưỡng support giống nhau, tập kết quả về mặt logic phải giống nhau
- Apriori tìm kiếm theo chiều rộng, sinh candidate itemset \(C_k\), cắt tỉa và đếm support theo từng mức
- FP-Growth không sinh candidate itemset; thuật toán nén dữ liệu bằng FP-tree rồi khai phá các conditional pattern base và conditional FP-tree
- Vì chiến lược tìm kiếm, số phép kiểm tra và số lần truy cập dữ liệu khác nhau, thời gian chạy có thể khác nhau đáng kể

FP-Growth thay chiến lược “generate-and-test” bằng khai phá pattern fragment trên FP-tree, nhờ đó tránh chi phí sinh ứng viên mà Apriori có thể gặp phải khi số candidate set lớn.
